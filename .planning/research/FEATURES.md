# AI Agent 平台功能全景研究 (2025)

> 研究日期: 2026-04-26
> 项目背景: AI Chat 玩具 - 具备 RAG/A2A/HITL 能力的 AI 对话平台

---

## 一、Table-Stakes 功能 (必具备 - 用户期望的基线)

这些功能如果没有，用户会立即流失。

### 1.1 对话核心

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **SSE 流式响应** | 打字机效果，实时 token 输出 | 低 | MiniMax API |
| **多轮对话记忆** | 滑动窗口记住上下文 (通常 10-20 轮) | 低 | Token 管理 |
| **流式中断/取消** | 用户可随时取消正在生成的响应 | 中 | 取消机制 (Event-style) |
| **Markdown 渲染** | 代码高亮、表格、列表 | 低 | shiki + dompurify |
| **意图识别** | 识别用户想做什么 (闲聊/工具/知识问答) | 中 | IntentClassifier |

### 1.2 模型支持

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **模型切换** | 用户可选不同模型 (M2.7/VL-01/Text-01) | 低 | ModelRouter |
| **Token 限制显示** | 显示当前上下文 token 消耗 | 低 | Token 计数器 |
| **自动摘要** | 上下文超长时自动压缩 | 中 | MemoryWindowManager |

### 1.3 工具系统

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **工具调用** | Agent 可调用外部工具 (搜索/计算等) | 中 | ToolExecutor |
| **工具超时控制** | 工具执行不能无限等待 | 中 | executeWithTimeout |
| **工具参数验证** | 防止无效参数导致崩溃 | 中 | _validateParameters |

### 1.4 基础安全

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **CORS 保护** | 限制跨域访问 | 低 | middleware |
| **速率限制** | 防止滥用 (如 100 req/min) | 低 | RateLimiter |
| **请求体大小限制** | 防大型攻击 (10MB) | 低 | middleware |
| **安全响应头** | X-Frame-Options, X-XSS-Protection | 低 | middleware |

### 1.5 RAG 基础

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **向量存储** | 文档向量化后存储 (Qdrant) | 中 | QdrantRouter |
| **相似度搜索** | Top-K 语义检索 | 低 | VectorSearch |
| **结果引用** | 标注答案来源 | 低 | CitationAssembler |

## 二、Differentiators (差异化优势 - 竞争制高点)

这些功能区分普通平台和优质平台。

### 2.1 Agent 能力

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **ReAct 执行循环** | 思考-行动-观察循环，透明化推理 | 高 | AgentEngine |
| **思维链可视化** | 显示 AI 的推理步骤 | 中 | ThinkingChain 组件 |
| **多 Agent 协作 (A2A)** | 多个专业 Agent 分工合作 | 高 | A2A Service |
| **Agent 记忆持久化** | Session Note Tool，跨会话记忆 | 中 | SemanticMemory |
| **意图澄清引导** | 低置信度时反问用户，不是硬猜 | 中 | IntentClassifier |

### 2.2 RAG 高级能力

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **问题重写 (Query Rewrite)** | 补全省略信息，恢复指代 | 高 | QueryRewriteService |
| **问题拆分 (Query Decompose)** | 复杂问题拆成多个子问题 | 高 | QueryDecomposeService |
| **多路检索** | 向量 + 关键词混合召回 | 高 | SearchCoordinator |
| **重排序 (Rerank)** | CrossEncoder/BM25 多策略重排 | 高 | Reranker |
| **文档摄取 Pipeline** | Parse→Chunk→Embedding→Index | 高 | IngestionPipeline |
| **Ollama 本地向量** | 无需云服务，保护数据隐私 | 中 | OllamaRouter |

### 2.3 HITL 人机协作

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **危险操作确认** | 删除/格式化等高危操作需人工确认 | 中 | HITL routes |
| **操作倒计时** | 60 秒超时自动取消 | 低 | 定时器 |
| **键盘快捷键** | Y/N/C 快速响应 | 低 | 前端监听 |
| **SSE 实时通知** | 操作状态实时推送到前端 | 中 | SSE Service |
| **风险等级颜色** | 红色高危/黄色中危 | 低 | UI 组件 |

### 2.4 生产级特性

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **熔断降级** | 模型失败时自动切换备选 | 高 | CircuitBreaker |
| **结构化日志** | JSON Lines 格式，traceId 追踪 | 中 | AgentLogger |
| **全链路追踪** | Trace ID 贯穿所有请求 | 高 | tracingService |

| **告警管理** | critical/warning/info 三级告警 | 中 | AlertManager |
| **配置中心热更新** | 无需重启修改配置 | 中 | ConfigCenter |
| **优先级队列** | 不同优先级任务调度 | 高 | QueueManager |

### 2.5 模型路由

| 功能 | 说明 | 复杂度 | 依赖 |
|------|------|--------|------|
| **主备模型切换** | 主模型失败自动切换 | 中 | ModelRouter |
| **模型健康检查** | 定期探测模型可用性 | 中 | HealthChecker |
| **首包探测** | 避免半截脏数据 | 低 | ProbeBufferingCallback |

## 三、Anti-Features (反模式 - 不要做)

这些是用户最讨厌的功能，设计时要避免。

### 3.1 对话类反模式

| 反模式 | 说明 | 影响 |
|--------|------|------|
| **模拟回复 / Lorem ipsum** | 实际调用了 API 却返回假数据 | 严重 - 失去信任 |
| **无法取消** | 用户按了取消但 AI 继续生成 | 严重 - 用户失控感 |
| **上下文丢失** | 刷新页面后对话历史消失 | 严重 - 资产损失 |
| **强制评价** | 每次对话结束强制打分 | 中等 - 中断流程 |
| **过度摘要** | AI 在不应该的地方做摘要 | 中等 - 体验割裂 |

### 3.2 RAG 类反模式

| 反模式 | 说明 | 影响 |
|--------|------|------|
| **返回无来源答案** | 答案没有标注来自哪个文档 | 严重 - 不可信 |
| **幻觉回答** | 知识库没有的内容 AI 瞎编 | 严重 - 错误答案 |
| **检索超时** | 向量搜索等太久，用户超时 | 中等 - 体验差 |
| **硬切分** | 按固定字数切分导致语义断裂 | 中等 - 答案不完整 |

### 3.3 Agent 类反模式

| 反模式 | 说明 | 影响 |
|--------|------|------|
| **黑盒执行** | 工具调用用户完全看不见 | 严重 - 不透明 |
| **无限循环** | Agent 陷入工具调用的死循环 | 严重 - 系统卡死 |
| **工具失败静默** | 工具报错但 AI 假装成功了 | 严重 - 数据不一致 |
| **无超时保护** | 工具执行可能永远等待 | 严重 - 系统资源耗尽 |

### 3.4 安全类反模式

| 反模式 | 说明 | 影响 |
|--------|------|------|
| **API Key 暴露在前端** | 直接在代码里写 API Key | 严重 - 安全事故 |
| **无速率限制** | 恶意用户可以无限请求 | 严重 - 服务崩溃 |
| **敏感数据日志** | 把用户输入打印到日志 | 严重 - 隐私泄露 |

### 3.5 HITL 类反模式

| 反模式 | 说明 | 影响 |
|--------|------|------|
| **确认框无倒计时** | 用户不知道要等多久 | 中等 - 焦虑 |
| **危险操作无确认** | 直接执行删除等操作 | 严重 - 数据损失 |
| **误触无法撤回** | 确认后不能撤销 | 中等 - 用户恐惧 |

## 四、HITL 系统期望能力

### 4.1 标准 HITL 功能

| 功能 | 说明 | 复杂度 |
|------|------|--------|
| **确认对话框** | 显示操作详情、风险等级 | 低 |
| **倒计时进度条** | 60 秒超时，视觉化进度 | 低 |
| **键盘快捷键** | Y 确认 / N 拒绝 / C 取消 | 低 |
| **SSE 实时订阅** | 前端实时接收确认状态更新 | 中 |
| **操作日志** | 记录所有确认请求和响应 | 低 |

### 4.2 高级 HITL 功能

| 功能 | 说明 | 复杂度 |
|------|------|--------|
| **风险等级自动判定** | 根据操作类型自动评级 | 中 |
| **批量操作合并确认** | 多个相似操作合并为一次确认 | 高 |
| **确认超时自动执行** | 可配置超时后自动批准 | 中 |
| **审批流程编排** | 支持多级审批链 | 高 |
| **草稿预览** | 确认前预览将执行的变更 | 中 |

### 4.3 HITL 触发场景

| 场景 | 风险等级 | 说明 |
|------|----------|------|
| 文件删除 / 格式化 | 高危 | 不可逆操作 |
| DROP / TRUNCATE 表 | 高危 | 数据库危险操作 |
| 批量覆盖数据 | 高危 | 数据覆盖 |
| GPT-4/5 / 图像生成调用 | 中危 | 高费用调用 |
| 外部 HTTP 请求 | 可选 | 隐私/安全 |

## 五、RAG 功能分层 (Standard vs Advanced)

### 5.1 Standard RAG (基础必备)

| 功能 | 说明 |
|------|------|
| **文档上传** | 支持 PDF/TXT/MD 等格式 |
| **分块 (Chunking)** | 固定大小或段落切分 |
| **向量化** | Embedding 模型转换 |
| **向量存储** | Qdrant 等向量数据库 |
| **Top-K 检索** | 语义相似度搜索 |
| **结果拼装** | 检索结果注入 Prompt |
| **来源标注** | 答案标注引用的文档 |

### 5.2 Advanced RAG (差异化能力)

| 功能 | 说明 | 复杂度 |
|------|------|--------|
| **问题重写 (Query Rewrite)** | 补全上下文/指代消解 | 高 |
| **问题拆分 (Query Decompose)** | 复杂问题拆子问题并行检索 | 高 |
| **HyDE (假设性文档)** | 用 AI 生成的假设答案引导检索 | 高 |
| **多路召回** | 向量 + 关键词 + BM25 并行 | 高 |
| **重排序 (Rerank)** | CrossEncoder 对结果二次排序 | 高 |
| **元数据过滤** | 支持时间/类别等条件过滤 | 中 |
| **混合检索** | 稠密向量 + 稀疏 BM25 | 高 |
| **增量索引** | 新文档无需全量重建 | 中 |
| **自省检索** | Agent 自我评估检索结果质量 | 高 |
| **引用追溯** | 精确到句子级别的来源 | 中 |

### 5.3 Enterprise RAG (大规模生产所需)

| 功能 | 说明 | 复杂度 |
|------|------|--------|
| **分布式向量存储** | 支持海量向量水平扩展 | 高 |
| **异步索引** | 文档上传后后台处理，不阻塞 | 中 |
| **Pipeline 监控** | 每个节点耗时/成功率监控 | 高 |
| **版本管理** | 文档更新后版本追踪 | 中 |
| **访问控制** | 不同用户看到不同知识库 | 高 |
| **数据血缘** | 追踪数据从来源到答案的完整路径 | 高 |

## 八、关键发现

### 8.1 AI Chat 玩具的竞争优势

项目已在以下方面形成竞争优势:
- **RAG 多策略重排序** (CrossEncoder/BM25/Semantic/Diversity) - 高于行业标准
- **问题重写 + 拆分** - 复杂问题处理能力突出
- **HITL 完整实现** - 11 个端点，风险等级/倒计时/快捷键齐全
- **生产级监控** - MetricsCollector/AlertManager/ConfigCenter 三件套
- **A2A 多 Agent 协作** - 支持 team_leader/collaborative/autonomous 三种模式

### 8.2 差距分析

| 优先级 | 差距 | 说明 |
|--------|------|------|
| P1 | 分布式向量存储 | Qdrant 单机，文档量大会成为瓶颈 |
| P1 | 访问控制 | 不同用户无法看到不同知识库 |
| P2 | HyDE | 假设性文档引导检索，提高召回率 |
| P2 | 数据血缘 | 企业合规需要 |
| P3 | 异步索引 Pipeline | 文档上传非阻塞处理 |

### 8.3 反模式检查

项目中已避免的反模式:
- ✅ 无 Lorem ipsum 模拟回复
- ✅ 有取消机制
- ✅ 有来源标注
- ✅ 工具调用有超时保护
- ✅ API Key 不暴露在前端
