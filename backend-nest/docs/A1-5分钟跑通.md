# NestJS后端 - 5分钟跑通

## 这是什么？
NestJS 框架构建的企业级后端服务
- 端口：3000
- 特性：依赖注入、装饰器路由、模块化架构

## 环境准备
- Node.js 18+
- npm 或 yarn

## 第一步：进入目录（1分钟）
```bash
cd backend-nest
```

## 第二步：安装依赖（2分钟）
```bash
npm install
```

## 第三步：启动开发服务器（1分钟）
```bash
npm run start:dev
```

## 第四步：验证（1分钟）
```bash
curl http://localhost:3000
```
应该返回 `Hello World!`

## 发生了什么？
```
启动命令 → NestJS 加载模块 → 扫描装饰器
                                     ↓
                            路由自动注册
                                     ↓
                         HTTP 服务器监听 3000 端口
```

## NestJS 核心概念

### 1. 模块（Module）
模块是组织代码的基本单位：
```typescript
// app.module.ts
@Module({
  imports: [],      // 引入其他模块
  controllers: [],  // 控制器
  providers: []     // 服务（依赖注入）
})
export class AppModule {}
```

### 2. 控制器（Controller）
处理 HTTP 请求：
```typescript
// app.controller.ts
@Controller()
export class AppController {
  constructor(private readonly appService: AppService) {}

  @Get()
  getHello(): string {
    return this.appService.getHello();
  }

  @Post('chat')
  sendMessage(@Body() body: { message: string }) {
    return this.appService.sendMessage(body.message);
  }
}
```

### 3. 服务（Service）
业务逻辑（使用依赖注入）：
```typescript
// app.service.ts
@Injectable()
export class AppService {
  getHello(): string {
    return 'Hello World!';
  }

  sendMessage(message: string): string {
    return `收到: ${message}`;
  }
}
```

## 项目结构
```
backend-nest/src/
├── app.module.ts      # 根模块
├── main.ts           # 入口文件
├── app.controller.ts  # 控制器
└── app.service.ts    # 服务
```

## 常见问题

Q: 端口被占用？
A: 修改 `main.ts` 中的 `listen()` 参数，或设置 `PORT` 环境变量

Q: 改动代码没生效？
A: 确保使用 `npm run start:dev`（热重载），而不是 `npm run start`

Q: 依赖注入失败？
A: 检查是否在 `@Injectable()` 装饰的类中使用，以及是否在模块的 `providers` 中声明
