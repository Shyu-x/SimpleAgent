# 依赖注入原理 - NestJS IoC 容器

## 核心问题
为什么要反转控制？直接创建依赖有什么问题？

## 传统方式的问题

### 手动创建依赖
```typescript
// 传统方式：自己创建依赖
class UserController {
  private userService: UserService;

  constructor() {
    this.userService = new UserService();  // 紧耦合
  }

  getUser(id: string) {
    return this.userService.findById(id);
  }
}
```

### 问题
1. **紧耦合**：Controller 直接依赖具体实现
2. **难以测试**：无法替换为 Mock 对象
3. **扩展困难**：替换实现需要修改代码

## 依赖注入解决方案

### DI 方式
```typescript
// DI 方式：由容器注入
@Controller()
export class UserController {
  // 只需要声明，NestJS 自动注入
  constructor(private readonly userService: UserService) {}

  getUser(id: string) {
    return this.userService.findById(id);
  }
}
```

### 好处
1. **松耦合**：依赖接口而非实现
2. **易测试**：可以注入 Mock 对象
3. **可替换**：轻松切换实现

## NestJS 中的实现

### 1. @Injectable() 装饰器
声明一个类可以被注入：
```typescript
@Injectable()
export class UserService {
  private users = [];

  findById(id: string) {
    return this.users.find(u => u.id === id);
  }

  create(data: CreateUserDto) {
    const user = { id: Date.now().toString(), ...data };
    this.users.push(user);
    return user;
  }
}
```

### 2. 自动注入
在构造函数中声明依赖：
```typescript
@Controller('users')
export class UserController {
  // NestJS 会自动注入 userService 实例
  constructor(private readonly userService: UserService) {}

  @Get(':id')
  findOne(@Param('id') id: string) {
    return this.userService.findById(id);
  }

  @Post()
  create(@Body() createUserDto: CreateUserDto) {
    return this.userService.create(createUserDto);
  }
}
```

### 3. 模块注册
在模块的 `providers` 中声明：
```typescript
@Module({
  controllers: [UserController],
  providers: [UserService]  // 声明可注入的服务
})
export class UserModule {}
```

## IoC 容器工作原理

```
┌─────────────────────────────────────────────────────┐
│                    IoC 容器                         │
│                                                     │
│  1. 扫描 @Injectable() 装饰的类                      │
│  2. 分析构造函数依赖                                  │
│  3. 创建依赖图                                       │
│  4. 按顺序实例化（先创建依赖，再创建被依赖的类）          │
│  5. 注入到构造函数                                   │
└─────────────────────────────────────────────────────┘
```

### 示例：多层依赖
```typescript
@Injectable()
export class DatabaseService {
  connection = 'database connection';
}

@Injectable()
export class UserRepository {
  constructor(private db: DatabaseService) {}
  // 使用 db.connection
}

@Injectable()
export class UserService {
  constructor(private repo: UserRepository) {}
  // 使用 repo 进行数据库操作
}

@Controller()
export class UserController {
  constructor(private userService: UserService) {}
}
```

容器实例化顺序：`DatabaseService` → `UserRepository` → `UserService` → `UserController`

## Provider 作用域

### 1. DEFAULT（单例）
```typescript
@Injectable()  // 默认 scope
export class UserService {}
// 所有请求共享同一个实例
```

### 2. REQUEST（请求级别）
```typescript
@Injectable({ scope: Scope.REQUEST })
export class UserService {
  constructor(private readonly request: Request) {}
  // 每个请求创建一个新实例
}
```

### 3. TRANSIENT（临时）
```typescript
@Injectable({ scope: Scope.TRANSIENT })
export class NotificationService {}
// 每次注入创建一个新实例
```

## 自定义 Provider

### 1. 值 Provider
```typescript
// 注入常量
{
  provide: 'API_KEY',
  useValue: process.env.API_KEY
}
```

### 2. 工厂 Provider
```typescript
// 动态创建实例
{
  provide: 'DATABASE',
  useFactory: (config: ConfigService) => {
    return new Database(config);
  },
  inject: [ConfigService]  // 依赖其他 Provider
}
```

### 3. 类 Provider
```typescript
// 使用别名（当需要注入接口时）
{
  provide: 'IUserService',
  useClass: UserServiceImpl
}
```

## 新手常见问题

Q: 为什么不直接 `new`？
A: 解耦、便于测试、支持单例、灵活替换实现

Q: 循环依赖怎么办？
A: 重新设计架构，或使用 `forwardRef()`（不推荐）

Q: 如何调试 DI？
A: NestJS 会自动检测依赖错误并给出清晰提示
