# Node.js后端 - 5分钟跑通

## 这是什么？
Express.js 构建的 AI 对话后端服务
- 端口：30000
- 特性：SSE 流式响应、MiniMax API 集成、Agent 执行引擎

## 环境准备
- Node.js 18+
- MiniMax API Key（从 https://platform.minimaxi.com 获取）

## 第一步：进入后端目录（1分钟）
```bash
cd backend
```

## 第二步：安装依赖（2分钟）
```bash
npm install
```

## 第三步：配置环境变量（1分钟）
创建 `backend/.env` 文件：
```bash
# MiniMax Token Plan API（必需）
MINIMAX_API_KEY=your_api_key_here

# 端口配置（可选，默认 30000）
PORT=30000

# Ollama 向量模型（可选）
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_EMBEDDING_MODEL=mxbai-embed-large
```

## 第四步：启动服务（1分钟）
```bash
npm run dev
```

## 第五步：验证（1分钟）
```bash
curl http://localhost:30000/health
```
应该返回：
```json
{"status":"ok","timestamp":"..."}
```

## 测试聊天功能
```bash
curl -X POST http://localhost:30000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"你好"}'
```

## API 基础

| 端点 | 方法 | 说明 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/api/chat` | POST | 发送聊天消息（SSE 流式） |
| `/api/models` | GET | 获取可用模型 |

## 发生了什么？
```
前端 (8080) → POST /api/chat → Express 路由
                                      ↓
                               Agent 执行引擎
                                      ↓
                               MiniMax API
                                      ↓
前端 (8080) ← SSE 流式响应 ← Express
```

## 项目结构
```
backend/src/
├── routes/          # HTTP 路由（参数校验、响应格式）
├── services/       # 业务逻辑（聊天编排、Agent 执行）
├── domain/         # 核心业务（意图分类、工具选择、RAG）
├── infra/          # 基础设施（熔断、限流、缓存）
├── common/         # 通用基础（错误定义）
├── application/    # 应用编排（跨模块协调）
└── middleware/     # 中间件（安全、CORS）
```

## 常见问题

Q: 启动报错 `MINIMAX_API_KEY is required`
A: 必须配置 `.env` 文件，填入有效的 API Key

Q: SSE 请求无响应
A: 检查 MiniMax API Key 是否有效，或网络是否能访问 api.minimaxi.com

Q: 端口被占用
A: 修改 `.env` 中的 `PORT`，或运行 `lsof -i :30000` 查找进程

Q: 如何开启 DEBUG 日志？
A: 在 `.env` 中添加 `DEBUG=true`
