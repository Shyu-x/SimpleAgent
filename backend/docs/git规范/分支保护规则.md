# Git 分支保护规则配置指南
#
# 适用于 GitLab 和 GitHub
# 确保代码质量，防止误操作

---

## GitLab 分支保护配置

### 1. 进入项目设置

```
项目 → 设置 → 仓库 → 受保护的分支
```

### 2. 保护分支配置

#### main 分支（生产环境）

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| 分支名称 | `main` | 主生产分支 |
| 允许合并 | Maintainers | 只有维护者可以合并 |
| 允许推送 | No one | 禁止直接推送 |
| 要求mr审批 | ✓ | 必须有审批 |
| 审批人数 | ≥ 1 | 最少1人审批 |
| 要求状态检查 | ✓ | 必须通过 CI |
| 要求线性历史 | ✓ | 防止 merge commits |
| 强制推送 | 禁用 | 禁止强制推送 |

#### develop 分支（开发集成）

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| 分支名称 | `develop` | 开发集成分支 |
| 允许合并 | Developers + Maintainers | 开发者和维护者 |
| 允许推送 | Developers | 开发者可以推送 |
| 要求mr审批 | ✓ | 必须有审批 |
| 审批人数 | ≥ 1 | 最少1人审批 |
| 要求状态检查 | ✓ | 必须通过 CI |

#### release/* 分支（发布分支）

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| 分支名称 | `release/*` | 发布分支 |
| 允许合并 | Maintainers | 只有维护者 |
| 允许推送 | Maintainers | 只有维护者 |
| 要求mr审批 | ✓ | 必须审批 |
| 要求状态检查 | ✓ | 必须通过 CI |

### 3. 分支保护规则示例（YAML）

```yaml
# .gitlab/ci/protected-branches.yml
protected_branches:
  main:
    access_level: maintainer
    push_access_level: no_one
    merge_access_level: maintainer
    unprotect_access_level: maintainer
    code_owner_approval_required: true

  develop:
    access_level: developer
    push_access_level: developer
    merge_access_level: maintainer
    code_owner_approval_required: false

  release:
    access_level: maintainer
    push_access_level: maintainer
    merge_access_level: maintainer
    code_owner_approval_required: true
```

## GitHub 分支保护配置

### 1. 进入仓库设置

```
仓库 → Settings → Branches → Branch protection rules
```

### 2. 创建保护规则

点击 "Add rule"，配置以下选项：

#### main 分支规则

```
Rule name: main
Branch name pattern: main

☑ Require pull request reviews before merging
    - Required number of reviewers: 1
    - ✓ Dismiss stale reviews
    - ✓ Require approval from code owners
    - ✓ Allow specified actors to bypass pull request requirements (Maintainers)

☑ Require status checks to pass before merging
    - ✓ GitHub Actions (commitlint)
    - ✓ GitHub Actions (branchlint)
    - 其他 CI 检查...

☑ Require linear history
☑ Do not allow bypassing the above settings (Maintainers)
☑ Include administrators
☑ Do not allow force pushes
```

#### develop 分支规则

```
Rule name: develop
Branch name pattern: develop

☑ Require pull request reviews before merging
    - Required number of reviewers: 1

☑ Require status checks to pass before merging
    - ✓ GitHub Actions (commitlint)

☑ Include administrators
☑ Do not allow force pushes
```

#### release/* 分支规则

```
Rule name: release branches
Branch name pattern: release/*

☑ Require pull request reviews before merging
    - Required number of reviewers: 2

☑ Require status checks to pass before merging
    - ✓ GitHub Actions (commitlint)
    - ✓ CI/CD pipeline

☑ Require linear history
☑ Include administrators
☑ Do not allow force pushes
```

### 3. CODEOWNERS 文件

创建 `.github/CODEOWNERS` 文件：

```github
# 语法说明：每个分支/路径可以有不同的 owner

# 默认所有仓库管理者为 code owner
*       @your-org/admin-team

# 模块负责人
# 认证模块
/backend/src/modules/auth/    @your-org/auth-team
/frontend/src/features/auth/  @your-org/auth-team

# 订单模块
/frontend/src/features/order/ @your-org/order-team

# 管理后台
/frontend/src/features/admin/ @your-org/admin-team

# 基础设施
/infra/                       @your-org/devops-team
/.github/                     @your-org/devops-team

# 文档
/docs/                        @your-org/docs-team

# CI/CD 配置
.gitlab-ci.yml       @your-org/devops-team
.github/             @your-org/devops-team
```

## 分支保护检查清单

### main 分支必须满足

- [ ] 禁止直接推送
- [ ] 必须通过 Pull Request 合并
- [ ] 至少1人审批（建议2人）
- [ ] 必须通过所有 CI 检查
- [ ] 禁止强制推送
- [ ] 包含 administrators
- [ ] 要求线性历史（可选）

### develop 分支建议

- [ ] 禁止直接推送（推荐）
- [ ] 必须通过 PR 合并
- [ ] 至少1人审批
- [ ] 必须通过 CI 检查

### release 分支建议

- [ ] 限制推送权限
- [ ] 必须通过 PR 合并
- [ ] 必须通过 CI 检查
- [ ] 设置发布标签

## 绕过分支保护

### GitLab

只有 `Maintainer` 或更高权限可以绕过：
- 在 Merge Request 中选择 "Merge when pipeline succeeds"
- 添加 `--no-verify` 跳过钩子（不推荐）

### GitHub

在保护规则中配置允许的角色：
```yaml
# GitHub Actions 环境变量
ALLOW_BYPASS: maintainers
```

## 常见问题

### Q: 误将分支设为保护无法删除？
A: 联系 GitLab/GitHub 管理员移除保护

### Q: CI 失败但需要紧急合并？
A:
1. 创建临时分支修复问题
2. 通过 PR 合并到 main
3. 不要绕过 CI，只在极端紧急情况下使用

### Q: 如何临时允许某人绕过？
A: 在保护规则中添加 `Bypass for specific people` 配置

## 最佳实践

1. **最少权限原则**：只允许需要的人访问
2. **强制代码审查**：所有代码必须经过审查
3. **CI 门禁**：不通过测试不允许合并
4. **线性历史**：便于回溯和定位问题
5. **CODEOWNERS**：明确各模块负责人
