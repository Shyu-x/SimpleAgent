# 性能压测指南

## 概述

本目录包含 AI Chat 玩具项目的性能压测脚本，用于验证系统在高负载下的稳定性和性能。

## 压测脚本

### 1. chat-pressure.js

聊天接口压测脚本，测试 `/api/chat` 端点的性能指标。

```bash
# 运行所有场景（正常/峰值/极限）
node chat-pressure.js

# 仅运行正常负载 (10并发)
node chat-pressure.js --normal

# 仅运行峰值负载 (50并发)
node chat-pressure.js --peak

# 仅运行极限负载 (100并发)
node chat-pressure.js --stress
```

### 2. admin-pressure.js

管理后台压测脚本，测试所有 `/api/admin/*` 端点。

```bash
# 测试所有管理后台接口
node admin-pressure.js

# 仅测试知识库管理
node admin-pressure.js --knowledge

# 仅测试工具管理
node admin-pressure.js --tools

# 仅测试模型管理
node admin-pressure.js --model

# 仅测试统计接口
node admin-pressure.js --stats
```

### 3. concurrent-users.js

并发用户模拟脚本，模拟真实用户行为。

```bash
# 混合用户场景 (50用户)
node concurrent-users.js

# 轻度用户 (30用户)
node concurrent-users.js --light

# 中度用户 (50用户)
node concurrent-users.js --medium

# 重度用户 (20用户)
node concurrent-users.js --heavy
```

## 性能指标

### 延迟指标

| 指标 | 说明 | 正常阈值 | 峰值阈值 | 极限阈值 |
|------|------|---------|---------|---------|
| P50 | 中位数延迟 | < 500ms | < 500ms | < 800ms |
| P90 | 90分位延迟 | < 1000ms | < 1500ms | < 2000ms |
| P95 | 95分位延迟 | < 1500ms | < 2000ms | < 2500ms |
| P99 | 99分位延迟 | < 2000ms | < 3000ms | < 3000ms |

### QPS 指标

| 场景 | 最小 QPS | 目标 QPS | 最大 QPS |
|------|---------|---------|---------|
| 正常负载 | 30 | 50 | 80 |
| 峰值负载 | 50 | 100 | 150 |
| 极限负载 | 80 | 150 | 200 |

### 错误率指标

| 状态 | 错误率 | 说明 |
|------|--------|------|
| 成功 | < 0.1% | 绿色，正常运行 |
| 警告 | < 1% | 黄色，需要关注 |
| 严重 | < 5% | 橙色，需要处理 |
| 失败 | >= 5% | 红色，系统不可用 |

## 状态判断标准

### 整体状态

| 状态 | 条件 |
|------|------|
| PASS | 所有指标均在正常范围内 |
| WARNING | 至少一项指标达到警告阈值 |
| FAIL | 至少一项指标超过严重阈值 |

### 各项指标状态

| 状态 | 延迟条件 | QPS 条件 | 错误率条件 |
|------|---------|---------|-----------|
| OK | P99 < 阈值 | > 目标值 | < 0.1% |
| WARNING | P99 < 阈值*1.2 | > 目标值*0.8 | < 1% |
| CRITICAL | P99 >= 阈值*1.5 | < 目标值*0.5 | >= 5% |

## 运行前提

1. 确保后端服务已启动 (默认: http://localhost:30000)
2. 确保 MiniMax API Key 已配置
3. 建议在测试环境运行，避免影响生产环境

## 结果解读

### 正常结果

- 错误率 < 1%
- P99 延迟 < 3000ms
- QPS 达到目标值
- 无崩溃或超时

### 需要关注的信号

- 错误率 > 1%
- P99 延迟 > 5000ms
- QPS 明显下降
- 响应时间波动大

### 需要立即处理的信号

- 错误率 > 5%
- P99 延迟 > 10000ms
- 服务崩溃
- 熔断器触发

## 常见问题

### Q1: 请求超时

**原因**: 系统负载过高或后端服务异常

**解决**:
1. 检查后端服务日志
2. 降低并发数重试
3. 检查熔断器状态

### Q2: 错误率过高

**原因**: API 限流、连接池耗尽、或代码异常

**解决**:
1. 查看错误日志
2. 调整限流配置
3. 检查数据库连接池

### Q3: 延迟突然增加

**原因**: 触发熔断降级、外部 API 响应慢

**解决**:
1. 检查熔断器状态
2. 查看 MiniMax API 状态
3. 增加超时时间
