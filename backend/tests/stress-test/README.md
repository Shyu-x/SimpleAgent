# Qdrant 向量检索压测

## 概述

本压测套件用于评估 Qdrant 向量数据库在高压场景下的性能表现，包括并发处理、批量检索、延迟分布和降级机制。

## 测试场景

### 1. 并发测试
测试不同并发级别（10/50/100/200）下的性能表现：
- 延迟 P50/P90/P99
- QPS（每秒请求数）
- 错误率

### 2. 批量检索测试
测试不同批量大小（10/50/100）下的性能：
- 批量处理延迟
- 并行加速比

### 3. 延迟分布测试
执行 100 次检索，统计延迟分布：
- 最小/最大/平均延迟
- P50/P90/P95/P99 延迟
- 成功率

### 4. 降级机制测试
验证系统在高负载或 Qdrant 不可用时的降级能力：
- Qdrant 连接失败时的降级响应
- 降级模式性能
- 熔断器保护机制
- 熔断恢复机制
- 健康检查触发降级

### 5. 向量化性能测试
测试不同批量大小下的向量化性能。

### 6. 稳定性测试
长时间运行测试，验证系统稳定性。

## 运行命令

### 前置条件

1. **启动 Qdrant 服务**
```bash
# 使用 Docker 启动 Qdrant
docker run -d --name qdrant \
  -p 6333:6333 \
  -p 6334:6334 \
  qdrant/qdrant:latest

# 或使用现有服务
export QDRANT_HOST=localhost
export QDRANT_PORT=6333
```

2. **安装依赖**
```bash
cd backend
npm install
```

### 运行压测

```bash
# 运行完整压测
node tests/stress-test/qdrant-load-test.js

# 或使用 npm script（需在 package.json 中配置）
npm run test:stress:qdrant
```

## 性能基线

### 延迟要求

| 指标 | 基线 | 说明 |
|------|------|------|
| P50 | < 50ms | 中位数延迟 |
| P90 | < 100ms | 90 分位延迟 |
| P99 | < 200ms | 99 分位延迟 |

### 吞吐量要求

| 指标 | 基线 | 说明 |
|------|------|------|
| 最小 QPS | 100 | 最低吞吐量 |
| 目标 QPS | 500 | 目标吞吐量 |

### 错误率要求

| 指标 | 基线 | 说明 |
|------|------|------|
| 最大错误率 | 1% | 正常运行错误率 |
| 严重阈值 | 5% | 触发告警阈值 |

### 降级机制要求

| 指标 | 基线 | 说明 |
|------|------|------|
| 最大延迟 | 500ms | 降级后最大延迟 |
| 最大错误率 | 10% | 降级后最大错误率 |

## 验收标准

压测通过需满足以下条件：

1. **并发测试**: 所有并发级别（10/50/100/200）下 P99 < 200ms
2. **QPS 测试**: 所有并发级别下 QPS >= 100
3. **延迟分布**: P50 < 50ms, P90 < 100ms, P99 < 200ms
4. **错误率**: 所有测试错误率 < 1%
5. **降级测试**: 降级模式可用且延迟 < 500ms
6. **稳定性**: 长时间运行错误率 < 1%

## 配置说明

配置文件 `config.js` 包含以下配置项：

### Qdrant 连接配置
```javascript
qdrant: {
  host: 'localhost',
  port: '6333',
  collection: 'chat_documents',
  dimension: 1024,
}
```

### 并发级别配置
```javascript
concurrency: {
  levels: [10, 50, 100, 200],  // 并发级别
  warmupRequests: 5,            // 预热请求数
  cooldownMs: 1000,             // 冷却时间
}
```

### 性能基线配置
```javascript
baselines: {
  latency: { p50: 50, p90: 100, p99: 200 },
  throughput: { minQps: 100, targetQps: 500 },
  errorRate: { max: 0.01, critical: 0.05 },
  fallback: { maxLatency: 500, maxErrorRate: 0.1 },
}
```

## 架构说明

### 降级机制

系统采用多级降级策略：

```
┌─────────────────────────────────────────────────────────────┐
│                     请求入口                                 │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│              健康检查 + 熔断器 (CircuitBreaker)             │
│  - 连续失败 5 次触发熔断                                     │
│  - 10 秒后尝试恢复                                          │
│  - HALF_OPEN 探测                                           │
└─────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────┴───────────────┐
              │                               │
              ▼                               ▼
┌─────────────────────────┐   ┌─────────────────────────────┐
│   Qdrant 正常模式         │   │   Qdrant 不可用              │
│   - 向量检索              │   │   - simpleVectorize 降级     │
│   - 实际数据库操作         │   │   - 128维向量生成            │
│   - HNSW + PQ 优化        │   │   - 填充到目标维度           │
└─────────────────────────┘   └─────────────────────────────┘
```

### 熔断器状态

```
CLOSED ──(失败触发)──> OPEN ──(超时)──> HALF_OPEN
   ^                      │                │
   │                      │                │
   └──(成功阈值)───────────┴──────(失败)───>┘
```

## 故障排查

### Qdrant 连接失败

```bash
# 检查 Qdrant 是否运行
curl http://localhost:6333/collections

# 查看 Qdrant 日志
docker logs qdrant
```

### 延迟过高

可能原因：
- Qdrant HNSW 参数配置不当
- 机器资源不足
- 网络延迟

解决方案：
- 调整 `hnsw_m` 和 `ef_construction` 参数
- 增加机器资源
- 使用内网连接

### 内存溢出

可能原因：
- 向量维度设置过大
- 批量插入数据量过大

解决方案：
- 降低向量维度（1024 -> 768 -> 512）
- 减小批量大小
