# 设计模式应用 - 策略/工厂/装饰器模式

## 核心问题
代码中的设计模式是如何解决实际问题的？

## 项目中的设计模式

### 1. 策略模式 (Strategy Pattern)

#### 问题
需要根据不同情况选择不同的算法/策略

#### 场景：RAG 多策略重排序
```javascript
// domain/rag/Reranker.js
class Reranker {
  constructor() {
    this.strategies = {
      crossEncoder: new CrossEncoderStrategy(),
      bm25: new BM25Strategy(),
      semantic: new SemanticStrategy(),
      diversity: new DiversityStrategy(),
    };
  }

  rerank(query, documents, options = {}) {
    const { weights = {} } = options;

    // 根据配置选择策略
    const results = {};
    if (weights.crossEncoder) {
      results.crossEncoder = this.strategies.crossEncoder.rank(query, documents);
    }
    if (weights.bm25) {
      results.bm25 = this.strategies.bm25.rank(query, documents);
    }
    // ...
  }
}
```

#### 对比
```typescript
// 不用策略模式：if/else 地狱
function rerank(query, docs, type) {
  if (type === 'crossEncoder') {
    // 100 行代码
  } else if (type === 'bm25') {
    // 80 行代码
  } else if (type === 'semantic') {
    // 90 行代码
  }
  // ...
}

// 使用策略模式：清晰简洁
function rerank(query, docs, strategy) {
  return strategy.rank(query, docs);
}
```

### 2. 工厂模式 (Factory Pattern)

#### 问题
需要创建复杂对象，但不想暴露创建细节

#### 场景：模型客户端工厂
```javascript
// services/model/ModelClientFactory.js
class ModelClientFactory {
  static create(type) {
    switch (type) {
      case 'minimax':
        return new MiniMaxChatClient();
      case 'openai':
        return new OpenAIChatClient();
      case 'anthropic':
        return new AnthropicChatClient();
      default:
        throw new Error(`Unknown model type: ${type}`);
    }
  }
}

// 使用
const client = ModelClientFactory.create('minimax');
```

#### 工厂 + 依赖注入
```javascript
// 工厂可以接受配置
class ModelClientFactory {
  static create(type, config) {
    switch (type) {
      case 'minimax':
        return new MiniMaxChatClient(config.apiKey, config.baseUrl);
      case 'qdrant':
        return new QdrantVectorClient(config);  // Qdrant 向量存储
      default:
        throw new Error(`Unknown model type: ${type}`);
    }
  }
}

// 使用
const client = ModelClientFactory.create('minimax', {
  apiKey: process.env.MINIMAX_API_KEY,
  baseUrl: 'https://api.minimaxi.com'
});
```

### 3. 装饰器模式 (Decorator Pattern)

#### 问题
需要在不修改原有类的情况下，给对象添加新功能

#### 场景：熔断器包装
```javascript
// infra/circuitBreaker/CircuitBreaker.js
class CircuitBreaker {
  constructor(fn, options) {
    this.fn = fn;
    this.failureThreshold = options.failureThreshold || 5;
    this.state = 'CLOSED';
  }

  async execute() {
    if (this.state === 'OPEN') {
      throw new CircuitOpenError();
    }

    try {
      return await this.fn();
    } catch (error) {
      this.recordFailure();
      throw error;
    }
  }
}

// 使用：给普通函数添加熔断功能
const safeCallAPI = new CircuitBreaker(callAPI, {
  failureThreshold: 3
});

// 调用时就像调用原函数一样
const result = await safeCallAPI.execute();
```

#### 装饰器语法（ES6+）
```javascript
// 装饰器函数
function withCircuitBreaker(options) {
  return function(target, name, descriptor) {
    const original = descriptor.value;
    descriptor.value = async function(...args) {
      const breaker = new CircuitBreaker(() => original.apply(this, args), options);
      return breaker.execute();
    };
    return descriptor;
  };
}

// 使用
class MiniMaxRouter {
  @withCircuitBreaker({ failureThreshold: 3 })
  async callAPI(messages) {
    // 原有的 API 调用逻辑
  }
}
```

### 4. 观察者模式 (Observer Pattern)

#### 问题
当对象状态变化时，需要通知多个其他对象

#### 场景：SSE 事件通知
```javascript
// 简单的观察者实现
class EventEmitter {
  constructor() {
    this.listeners = {};
  }

  on(event, callback) {
    if (!this.listeners[event]) {
      this.listeners[event] = [];
    }
    this.listeners[event].push(callback);
  }

  emit(event, data) {
    if (this.listeners[event]) {
      this.listeners[event].forEach(cb => cb(data));
    }
  }

  off(event, callback) {
    if (this.listeners[event]) {
      this.listeners[event] = this.listeners[event].filter(cb => cb !== callback);
    }
  }
}

// 使用
const emitter = new EventEmitter();

emitter.on('message', (msg) => console.log('收到消息:', msg));
emitter.on('stream', (chunk) => console.log('流式数据:', chunk));

emitter.emit('message', { content: 'Hello' });
```

### 5. 单例模式 (Singleton Pattern)

#### 问题
某些对象只需要一个实例

#### 场景：配置中心
```javascript
// infra/config/ConfigCenter.js
class ConfigCenter {
  constructor() {
    if (ConfigCenter.instance) {
      return ConfigCenter.instance;
    }
    this.config = {};
    ConfigCenter.instance = this;
  }

  get(key) {
    return this.config[key];
  }

  set(key, value) {
    this.config[key] = value;
  }
}

// 全局只有一个实例
const config1 = new ConfigCenter();
const config2 = new ConfigCenter();
console.log(config1 === config2); // true
```

## 设计模式总结

| 模式 | 解决的问题 | 项目中的例子 |
|------|----------|-------------|
| **策略** | 多算法选择 | Reranker 多策略 |
| **工厂** | 复杂对象创建 | ModelClientFactory |
| **装饰器** | 功能扩展 | CircuitBreaker 包装 |
| **观察者** | 事件通知 | SSE EventEmitter |
| **单例** | 全局唯一实例 | ConfigCenter |

## 不用设计模式的后果

### 问题 1：条件地狱
```javascript
// 不用策略模式
function getResult(type, data) {
  if (type === 'A') {
    if (data.x > 10) {
      return handleTypeA1(data);
    } else {
      return handleTypeA2(data);
    }
  } else if (type === 'B') {
    // 又是一堆嵌套...
  }
  // 无限膨胀...
}
```

### 问题 2：紧耦合
```javascript
// 不用工厂模式
class ChatService {
  constructor() {
    // 直接依赖具体实现
    this.ai = new MiniMaxAI();
  }
}
// 换 AI 需要改 ChatService
```

### 问题 3：修改现有代码
```javascript
// 不用装饰器模式
class MiniMaxRouter {
  async callAPI() {
    // 如果要加熔断、重试、日志...
    // 必须直接修改这个方法
  }
}
// 违反开闭原则
```

## 新手常见问题

Q: 什么时候用设计模式？
A: 当代码出现 if/else 地狱、紧耦合、难以测试时，考虑设计模式

Q: 设计模式会不会过度设计？
A: 小项目避免过度抽象，先解决问题，再考虑模式

Q: 可以不用设计模式吗？
A: 可以！简单代码不需要模式，模式是工具不是教条
