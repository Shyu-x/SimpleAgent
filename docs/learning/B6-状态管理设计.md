# 状态管理设计 - 为什么需要状态管理？

## 核心问题
组件之间如何共享数据？如何跟踪数据变化？

## 前端状态管理的演进

### 1. 无状态（纯组件）
```jsx
// 数据通过 props 传入
function UserList({ users }) {
  return (
    <ul>
      {users.map(user => (
        <UserItem key={user.id} name={user.name} />
      ))}
    </ul>
  );
}
```

**问题**：深层嵌套时需要层层传递（Props Drilling）

### 2. Props Drilling（层层传递）
```
App → Layout → Sidebar → ConversationList → ConversationItem
                              ↓
                        只需要 ConversationItem
```
- 中间组件可能不需要这些数据
- 但必须传递下去
- 修改数据结构时很痛苦

### 3. Context（跨组件传递）
```jsx
// 创建 Context
const UserContext = createContext();

// Provider 包裹
<UserContext.Provider value={{ user, setUser }}>
  <App />
</UserContext.Provider>

// 任何子组件都可以使用
function Profile() {
  const { user } = useContext(UserContext);
  return <div>{user.name}</div>;
}
```

**问题**：
- 多个 Context 会导致组件重渲染
- 难以追踪哪个 Context 导致了更新
- 不适合复杂状态逻辑

### 4. 状态管理库（Zustand/Redux）
```typescript
// Zustand 示例
import { create } from 'zustand';

interface ChatState {
  messages: Message[];
  addMessage: (msg: Message) => void;
  clearMessages: () => void;
}

const useChatStore = create<ChatState>((set) => ({
  messages: [],
  addMessage: (msg) => set((state) => ({
    messages: [...state.messages, msg]
  })),
  clearMessages: () => set({ messages: [] })
}));

// 使用
function ChatArea() {
  const { messages, addMessage } = useChatStore();
  // ...
}
```

## Zustand 设计选择

### 为什么选择 Zustand？

| 方案 | 优点 | 缺点 | 复杂度 |
|------|------|------|--------|
| Redux | 功能强大、生态好 | 模板代码多、学习曲线陡 | 高 |
| Zustand | 极简API、轻量 | 功能相对少 | 低 |
| Context | 内置、无需依赖 | 性能问题 | 中 |

### Zustand 核心 API
```typescript
import { create } from 'zustand';

// 创建 Store
const useStore = create((set, get) => ({
  // 状态
  count: 0,

  // 更新函数
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),

  // 获取当前状态
  getCount: () => get().count
}));

// 在组件中使用
function Counter() {
  const { count, increment } = useStore();
  return <button onClick={increment}>{count}</button>;
}
```

## 在项目中的应用

### chatStore - 聊天状态
```typescript
// frontend/src/store/chatStore.ts
interface ChatState {
  // 消息列表
  messages: Message[];

  // 添加消息
  addMessage: (msg: Message) => void;

  // 加载历史
  loadHistory: (messages: Message[]) => void;

  // 清空
  clearMessages: () => void;

  // SSE 状态
  isStreaming: boolean;
  setStreaming: (streaming: boolean) => void;
}

const useChatStore = create<ChatState>((set, get) => ({
  messages: [],
  isStreaming: false,

  addMessage: (msg) => set((state) => ({
    messages: [...state.messages, msg]
  })),

  loadHistory: (messages) => set({ messages }),

  clearMessages: () => set({ messages: [] }),

  setStreaming: (streaming) => set({ isStreaming: streaming })
}));
```

### 持久化策略
```typescript
// sessionStorage 持久化（关闭浏览器消失）
const useChatStore = create(
  persist(

// 对比 localStorage（永久保存）
const usePersistentStore = create(
```

## 状态管理最佳实践

### 1. 按功能分离 Store
```typescript
// chatStore.ts - 聊天相关
// uiStore.ts - UI 状态
// userStore.ts - 用户相关

// 而不是一个大 Store 装所有东西
```

### 2. 避免派生状态
```typescript
// 不好：在组件中计算派生状态
function ChatArea() {
  const unreadCount = messages.filter(m => !m.read).length;
  // 问题：每次渲染都重新计算
}

// 好：用 Selector
const useUnreadCount = () => useChatStore(
  (state) => state.messages.filter(m => !m.read).length
);
```

### 3. 不可变性
```typescript
// 不好：直接修改
state.messages.push(newMessage);

// 好：创建新数组
set({ messages: [...state.messages, newMessage] });
```

## 新手常见问题

Q: 什么时候用 Zustand？
A: 中等复杂度、需要跨组件共享状态、状态需要持久化时

Q: State 和 Props 的区别？
A: Props 是父组件传入的，State 是组件自己管理的

Q: 为什么不都用 Context？
A: Context 会导致所有消费者重渲染，Zustand 可以精细控制

Q: Redux 和 Zustand 怎么选？
A: 小项目用 Zustand，大型复杂项目用 Redux
