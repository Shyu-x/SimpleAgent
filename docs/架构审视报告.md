## 三、前端架构问题

### 3.1 unifiedStore.ts 膨胀分析

**当前状态**: 640行，21个状态字段，46个方法

**问题**:
1. 对话状态 + 消息状态 + 备注状态 + 全局记忆 + 设置 + UI状态 混在一起
2. 持久化逻辑复杂（partialize + skipHydration + sessionStorageAdapter）
3. 复用困难：其他组件无法单独引用对话或消息

**建议拆分**:
```
stores/
├── conversationStore.ts   # 对话 CRUD、窗口配置 (250行)
├── messageStore.ts        # 消息操作、备注 (200行)
├── memoryStore.ts         # 全局记忆、customPrompts (150行)
├── uiStore.ts             # UI状态、设置 (150行)
└── unifiedStore.ts        # 组合以上 store (100行，向后兼容)
```

### 3.2 MissionControl 组件耦合

**当前问题**:
- `useMissionControlAPI` 直接在组件内调用
- 任务分配逻辑（`autoAssignTask`）在组件内实现
- 事件回调处理（`onEvent`/`onTaskComplete`/`onAllTasksComplete`）耦合

**建议**:
```typescript
// 抽取为独立 hook
const useMissionControl = (config: MissionControlConfig) => {
  const { syncTasks, syncAgents } = useMissionControlAPI();
  const { autoAssignTask } = useTaskAssignment();
  const { handleCallbacks } = useMissionCallbacks(config);

  // ... 组合逻辑
  return { /* 暴露给组件的接口 */ };
};
```

## 四、版本管理规范

### 4.1 分支策略建议

**当前问题**: 只有 `master` 分支，无分支模型

**建议采用 Git Flow 简化版**:

```
main (保护分支)
    ↑ PR 合并
    │
develop (开发分支)
    ↑ PR 合并
    │
feature/xxx-功能描述    # 功能开发
hotfix/xxx-问题描述     # 紧急修复
release/xxx            # 发布准备
```

**命名规范**:
- `feature/chat-sse-streaming` - 功能分支
- `hotfix/auth-token-expiry` - 紧急修复
- `release/v2.5.0` - 发布分支

### 4.2 Commit Message 规范

**当前配置**: `commitlint` + `Conventional Commits`

**已有规范**:
