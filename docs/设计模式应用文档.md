## 一、设计模式概览

| 模式 | 类型 | 应用场景 | 解决的问题 |
|------|------|---------|-----------|
| **策略模式** | 行为型 | SearchChannel, PostProcessor, ChatModelClient | 算法可替换，新增实现不修改已有代码 |
| **工厂模式** | 创建型 | ChatModelFactory, CircuitBreakerFactory | 复杂对象创建逻辑集中管理 |
| **模板方法** | 行为型 | IngestionPipeline, IngestionNode | 算法骨架固定，具体步骤可替换 |
| **装饰器** | 结构型 | ProbeBufferingCallback, CircuitBreaker | 动态增加功能，不修改原有类 |
| **门面模式** | 结构型 | SearchCoordinator | 封装复杂子系统，提供统一入口 |
| **责任链** | 行为型 | PostProcessor 链, Middleware 链 | 请求处理可组合、可动态调整 |
| **观察者** | 行为型 | EventEmitter, SSE | 状态变更通知，解耦发布/订阅 |
| **注册表** | 其他 | SearchChannelRegistry, ToolRegistry | 组件自动发现，新增组件零配置 |
| **单例** | 创建型 | breakerFactory, logger | 全局唯一实例，状态共享 |
| **代理** | 结构型 | CacheProxy | 访问控制，增加额外逻辑 |

## 二、策略模式

### 2.1 模式定义

**意图**: 定义一系列算法，把它们一个个封装起来，并且使它们可以相互替换。

**解决的问题**:
- 多种检索策略需要可切换
- 新增检索通道不应该修改已有代码
- 运行时需要根据配置选择不同策略

### 2.2 应用场景：检索通道

```javascript
// domain/search/SearchChannel.js
/**
 * 检索通道抽象基类
 * 所有检索通道必须实现此接口
 */
class SearchChannel {
  async search(query, options) {
    throw new Error('Not implemented');
  }

  get channelName() {
    throw new Error('Not implemented');
  }

  get channelType() {
    // 'vector' | 'keyword' | 'hybrid'
    throw new Error('Not implemented');
  }

  get priority() {
    return 100;
  }
}

// 向量检索通道
class VectorSearchChannel extends SearchChannel {
  constructor(options) {
    super();
    this.vectorStore = options.vectorStore;
    this.embeddingModel = options.embeddingModel;
  }

  get channelName() { return 'vector'; }
  get channelType() { return 'vector'; }
  get priority() { return 10; }

  async search(query, options) {
    const embedding = await this.embeddingModel.embed(query);
    return this.vectorStore.search(embedding, options);
  }
}

// 关键词检索通道
class KeywordSearchChannel extends SearchChannel {
  constructor(options) {
    super();
    this.documents = options.documents;
  }

  get channelName() { return 'keyword'; }
  get channelType() { return 'keyword'; }
  get priority() { return 20; }

  async search(query, options) {
    // BM25 算法实现
    return this.calculateBM25(query, this.documents);
  }
}

// 混合检索通道
class HybridSearchChannel extends SearchChannel {
  constructor(options) {
    super();
    this.vectorChannel = options.vectorChannel;
    this.keywordChannel = options.keywordChannel;
    this.weights = options.weights || { vector: 0.7, keyword: 0.3 };
  }

  get channelName() { return 'hybrid'; }
  get channelType() { return 'hybrid'; }
  get priority() { return 5; }

  async search(query, options) {
    const [vectorResults, keywordResults] = await Promise.all([
      this.vectorChannel.search(query, options),
      this.keywordChannel.search(query, options)
    ]);
    return this.mergeWithWeights(vectorResults, keywordResults, this.weights);
  }
}

// 使用
const vectorChannel = new VectorSearchChannel({ vectorStore, embeddingModel });
const keywordChannel = new KeywordSearchChannel({ documents });
const hybridChannel = new HybridSearchChannel({
  vectorChannel,
  keywordChannel,
  weights: { vector: 0.7, keyword: 0.3 }
});

// 运行时选择策略
const channels = {
  vector: vectorChannel,
  keyword: keywordChannel,
  hybrid: hybridChannel
};

const selectedChannel = channels[config.searchStrategy];
const results = await selectedChannel.search(query, options);
```

## 三、工厂模式

### 3.1 模式定义

**意图**: 定义一个创建对象的接口，让子类决定实例化哪一个类。

**解决的问题**:
- 复杂对象创建逻辑分散在各处
- 对象创建逻辑可能变化
- 需要统一管理对象创建

### 3.2 应用场景：模型客户端工厂

```javascript
// infra/llm/ChatModelFactory.js
/**
 * 聊天模型客户端工厂
 */
class ChatModelFactory {
  constructor() {
    this._creators = new Map();
  }

  /**
   * 注册创建器
   */
  register(type, creator) {
    this._creators.set(type, creator);
  }

  /**
   * 创建客户端
   */
  create(type, options) {
    const creator = this._creators.get(type);

    if (!creator) {
      throw new Error(`Unknown model type: ${type}`);
    }

    return creator.create(options);
  }

  /**
   * 创建所有已注册的客户端
   */
  createAll(configs) {
    const clients = new Map();

    for (const [type, options] of Object.entries(configs)) {
      try {
        const client = this.create(type, options);
        clients.set(type, client);
      } catch (error) {
        console.warn(`Failed to create client for ${type}:`, error.message);
      }
    }

    return clients;
  }
}

// 具体创建器
class MiniMaxCreator {
  create(options) {
    return new MiniMaxChatClient({
      apiKey: options.apiKey,
      baseUrl: options.baseUrl,
      model: options.model || 'MiniMax-M2.7-highspeed'
    });
  }
}

class OpenAICreator {
  create(options) {
    return new OpenAIChatClient({
      apiKey: options.apiKey,
      model: options.model || 'gpt-4'
    });
  }
}

// 注册
const factory = new ChatModelFactory();
factory.register('minimax', new MiniMaxCreator());
factory.register('openai', new OpenAICreator());

// 使用
const clients = factory.createAll({
  minimax: { apiKey: process.env.MINIMAX_API_KEY },
  openai: { apiKey: process.env.OPENAI_API_KEY }
});

const minimaxClient = factory.create('minimax', { apiKey: 'xxx' });
```

## 四、模板方法模式

### 4.1 模式定义

**意图**: 定义一个操作中的算法骨架，而将一些步骤延迟到子类中。

**解决的问题**:
- 算法骨架固定，但具体步骤可能变化
- 代码复用，减少重复
- 子类必须遵循特定流程

### 4.2 应用场景：文档入库流水线

```javascript
// domain/rag/ingestion/IngestionPipeline.js
/**
 * 文档入库流水线 - 模板方法
 */
class IngestionPipeline {
  constructor(nodes = []) {
    this.nodes = nodes;
  }

  /**
   * 执行流水线 - 模板方法
   * 这个方法定义了算法骨架，子类/节点不能修改
   */
  async process(document, options = {}) {
    const context = { document, traceId: options.traceId };
    const results = [];

    for (const node of this.nodes) {
      // 钩子：检查是否应该执行
      if (!node.shouldExecute(context)) {
        continue;
      }

      try {
        // 核心步骤：执行节点
        const result = await node.execute(context);

        // 钩子：后处理
        node.onSuccess && node.onSuccess(result);

        results.push({ node: node.nodeName, success: true, result });
        context[node.outputKey] = result;
      } catch (error) {
        // 钩子：错误处理
        const shouldContinue = node.onError && node.onError(error);

        results.push({ node: node.nodeName, success: false, error: error.message });

        if (!shouldContinue) {
          throw error;
        }
      }
    }

    return { context, results };
  }
}

// domain/rag/ingestion/nodes/IngestionNode.js
/**
 * 入库节点基类
 */
class IngestionNode {
  constructor(options = {}) {
    this.nodeName = options.name || this.constructor.name;
    this.order = options.order || 100;
    this.outputKey = options.outputKey || 'result';
  }

  /**
   * 钩子：是否应该执行
   */
  shouldExecute(context) {
    return true;
  }

  /**
   * 核心步骤：子类必须实现
   */
  async execute(context) {
    throw new Error('Not implemented');
  }

  /**
   * 钩子：成功时调用
   */
  onSuccess(result) {}

  /**
   * 钩子：失败时调用，返回 true 继续执行
   */
  onError(error) {
    return false;
  }
}

// 具体节点实现
class ParseNode extends IngestionNode {
  constructor(options) {
    super({ name: 'ParseNode', order: 10, outputKey: 'parsed' });
    this.supportedTypes = options.supportedTypes || ['.txt', '.md'];

    const { document } = context;

    if (!this.supportedTypes.includes(ext)) {

  }
}

  async execute(context) {
    const text = context.parsed?.text || context.document.content;
    return this.chunkText(text, this.chunkSize, this.overlap);

    // 分块逻辑
  }
}

// 使用
const pipeline = new IngestionPipeline([
```

## 五、装饰器模式

### 5.1 模式定义

**意图**: 动态地给对象添加一些额外的职责。

**解决的问题**:
- 需要增加功能，但不想修改原有类
- 功能需要动态添加/移除
- 继承会导致类爆炸

### 5.2 应用场景：首包探测

```javascript
// infra/sse/ProbeBufferingCallback.js
/**
 * 首包探测装饰器
 * 在不修改原有回调的前提下增加首包探测能力
 */
class ProbeBufferingCallback {
  constructor(originalCallback) {
    this.original = originalCallback;
    this.buffer = [];
    this.firstChunkReceived = false;
    this.probing = true; // 探测模式
  }

  /**
   * 装饰 onChunk
   */
  onChunk(chunk) {
    if (this.probing) {
      // 探测模式：缓冲所有数据
      this.buffer.push(chunk);

      // 检测是否为完整首包（简单的行/块检测）
      if (this.isFirstChunkComplete(chunk)) {
        this.firstChunkReceived = true;
        this.probing = false;

        // 清空缓冲区并发送
        for (const buffered of this.buffer) {
          this.original.onChunk(buffered);
        }
        this.buffer = [];
      }
    } else {
      // 正常模式：直接转发
      this.original.onChunk(chunk);
    }
  }

  onComplete() {
    // 探测完成，如果有剩余缓冲则发送
    if (!this.firstChunkReceived && this.buffer.length > 0) {
      for (const buffered of this.buffer) {
        this.original.onChunk(buffered);
      }
    }
    this.original.onComplete();
  }

  onError(error) {
    this.original.onError(error);
  }

  isFirstChunkComplete(chunk) {
    // 简单检测：是否包含完整的数据块
    // 例如：SSE 中是否包含空行，或固定大小块
    return chunk.endsWith('\n\n') || chunk.includes('[DONE]');
  }
}

// 使用
class OriginalSSEHandler {
  onChunk(chunk) {
    // 原有处理逻辑
    this.sendToClient(chunk);
  }

  onComplete() {
    this.finish();
  }
}

const handler = new OriginalSSEHandler();
const decoratedHandler = new ProbeBufferingCallback(handler);

// SSE 数据流经过装饰器
sseStream.on('data', (chunk) => {
  decoratedHandler.onChunk(chunk.toString());
});
```

### 5.3 面试亮点

> **STAR 描述**:
> - Situation: 模型切换时会出现半截数据，导致用户体验差
> - Task: 在不修改原有 SSE 处理逻辑的前提下，增加首包探测能力
> - Action: 使用装饰器模式封装原有回调，探测到完整首包后再开始发送
> - Result: 模型切换对用户完全无感知，装饰器可独立测试和复用

## 六、门面模式

### 6.1 模式定义

**意图**: 为子系统中的一组接口提供一个一致的界面。

**解决的问题**:
- 子系统复杂，调用困难
- 简化客户端调用
- 解耦客户端和子系统

### 6.2 应用场景：检索协调器

```javascript
// domain/search/SearchCoordinator.js
/**
 * 检索协调器 - 门面类
 * 封装多通道并行执行和后处理流水线
 */
class SearchCoordinator {
  constructor(channels, postProcessors) {
    this.channels = channels;
    this.postProcessors = postProcessors;
  }

  /**
   * 统一的检索入口
   * 客户端无需知道内部有多少通道、如何并行、如何后处理
   */
  async search(query, options = {}) {
    // 1. 并行执行所有通道
    const channelResults = await this.executeChannels(query, options);

    // 2. 合并结果
    const merged = this.mergeResults(channelResults);

    // 3. 后处理流水线
    let processed = merged;
    for (const processor of this.postProcessors) {
      processed = await processor.process(processed, query);
    }

    return processed;
  }

  /**
   * 内部实现，对客户端隐藏
   */
  async executeChannels(query, options) {
    // 并行执行
    return Promise.all(
      this.channels.map(channel => channel.search(query, options))
    );
  }

  mergeResults(results) {
    // 合并逻辑
  }
}

// 使用
const coordinator = new SearchCoordinator(
  [
    new VectorSearchChannel({ vectorStore }),
    new KeywordSearchChannel({ documents }),
    new HybridSearchChannel({ vectorChannel, keywordChannel })
  ],
  [
    new DeduplicationProcessor(),
    new RerankerProcessor({ llmClient }),
    new ThresholdFilterProcessor({ threshold: 0.5 })
  ]
);

// 客户端只需调用一个方法
const results = await coordinator.search('如何配置 Docker', { topK: 5 });
```

## 七、责任链模式

### 7.1 模式定义

**意图**: 将请求沿着处理者链传递，直到有一个处理者处理它。

**解决的问题**:
- 请求处理需要经过多个步骤
- 处理顺序需要可配置
- 新增/移除处理步骤不应影响其他步骤

### 7.2 应用场景：后处理器链

```javascript
// domain/search/postProcessors/ProcessorChain.js
/**
 * 后处理器链
 */
class ProcessorChain {
  constructor() {
    this.processors = [];
  }

  /**
   * 添加处理器
   */
  add(processor) {
    this.processors.push(processor);
    return this; // 链式调用
  }

  /**
   * 执行链
   */
  async process(results, query) {
    let current = results;

    for (const processor of this.processors) {
      if (processor.enabled !== false) {
        current = await processor.process(current, query);
      }
    }

    return current;
  }
}

// 具体处理器
class DeduplicationProcessor {
  async process(results, query) {
    if (results.length <= 1) return results;

    const unique = [];
    for (const result of results) {
      const isDup = unique.some(existing =>
        this.similarity(result.content, existing.content) > 0.85
      );
      if (!isDup) unique.push(result);
    }
    return unique;
  }
}

class RerankerProcessor {
  async process(results, query) {
    if (results.length <= 1) return results;

    const scored = await this.llmClient.evaluate(query, results);
    return scored.sort((a, b) => b.score - a.score);
  }
}

class ThresholdFilterProcessor {
  constructor(options) {
    this.threshold = options.threshold || 0.5;
  }

  async process(results, query) {
    return results.filter(r => r.score >= this.threshold);
  }
}

// 使用
const chain = new ProcessorChain()
  .add(new DeduplicationProcessor())
  .add(new RerankerProcessor({ llmClient }))
  .add(new ThresholdFilterProcessor({ threshold: 0.5 }));

const processed = await chain.process(rawResults, query);
```

### 7.3 面试亮点

> **STAR 描述**:
> - Situation: 检索结果需要去重、重排序、过滤等多个后处理步骤，顺序固定但可能动态调整
> - Task: 设计可组合、可配置的后处理流程
> - Action: 使用责任链模式，每种处理作为独立处理器，支持运行时链式组装
> - Result: 后处理流程可在配置中调整，无需修改代码；处理器可独立测试

## 八、观察者模式

### 8.1 模式定义

**意图**: 定义对象间的一种一对多的依赖关系，当一个对象状态改变时，所有依赖它的对象都会收到通知。

**解决的问题**:
- 状态变更需要通知多个对象
- 解耦发布和订阅
- 支持事件驱动的通信

### 8.2 应用场景：SSE 事件流

```javascript
// infra/sse/SseEmitterWrapper.js
/**
 * SSE 发射器封装
 * 支持多订阅者
 */
class SseEmitterWrapper {
  constructor() {
    this.subscribers = new Map(); // sessionId -> response
    this.eventHandlers = new Map(); // eventType -> [handlers]
  }

  /**
   * 添加订阅者
   */
  subscribe(sessionId, response) {
    this.subscribers.set(sessionId, response);
  }

  /**
   * 取消订阅
   */
  unsubscribe(sessionId) {
    this.subscribers.delete(sessionId);
  }

  /**
   * 注册事件处理器
   */
  on(eventType, handler) {
    if (!this.eventHandlers.has(eventType)) {
      this.eventHandlers.set(eventType, []);
    }
    this.eventHandlers.get(eventType).push(handler);
  }

  /**
   * 发送事件给所有订阅者
   */
  send(eventType, data) {
    const payload = `event: ${eventType}\ndata: ${JSON.stringify(data)}\n\n`;

    // 发送给所有订阅者
    for (const [sessionId, response] of this.subscribers) {
      try {
        response.write(payload);
      } catch (error) {
        // 订阅者断开，移除
        this.unsubscribe(sessionId);
      }
    }

    // 触发事件处理器
    const handlers = this.eventHandlers.get(eventType) || [];
    for (const handler of handlers) {
      handler(data);
    }
  }

  /**
   * 发送消息事件
   */
  sendMessage(content, done = false) {
    this.send('message', { content, done });
  }

  /**
   * 发送错误事件
   */
  sendError(code, message) {
    this.send('error', { code, message });
  }

  /**
   * 发送完成事件
   */
  sendDone(usage) {
    this.send('done', { usage });
  }
}

// 使用
const emitter = new SseEmitterWrapper();

emitter.subscribe(sessionId, res);

// 注册监控
emitter.on('error', (data) => {
  metrics.increment('sse.error', { code: data.code });
});

// Agent 执行过程中发送事件
```

## 九、注册表模式

### 9.1 模式定义

**意图**: 集中管理组件注册，支持自动发现和零配置扩展。

**解决的问题**:
- 组件需要集中管理
- 支持运行时动态注册
- 自动发现并加载组件

### 9.2 应用场景：工具注册表

```javascript
// services/tools/ToolRegistry.js
/**
 * 工具注册表
 * 支持自动发现和运行时注册
 */
class ToolRegistry {
  constructor() {
    this._tools = new Map(); // name -> Tool
    this._categories = new Map(); // category -> Set<Tool>
  }

  /**
   * 注册工具
   */
  register(tool) {
    if (!(tool instanceof Tool)) {
      throw new Error('Must be instanceof Tool');
    }

    this._tools.set(tool.name, tool);

    if (!this._categories.has(tool.category)) {
      this._categories.set(tool.category, new Set());
    }
    this._categories.get(tool.category).add(tool);
  }

  /**
   * 获取工具
   */
  get(name) {
    return this._tools.get(name);
  }

  /**
   * 获取所有工具
   */
  getAll() {
    return Array.from(this._tools.values());
  }

  /**
   * 按类别获取
   */
  getByCategory(category) {
    return Array.from(this._categories.get(category) || []);
  }

  /**
   * 查找可用工具
   */
  findTools(task) {
    return this.getAll().filter(tool => tool.canHandle(task));
  }

  /**
   * 自动发现 - 扫描目录加载工具
   */
  async discover(directory) {
    const files = fs.readdirSync(directory);

    for (const file of files) {
      if (!file.endsWith('Tool.js')) continue;

      const ToolClass = require(path.join(directory, file));
      const tool = new ToolClass();

      // 注入依赖
      if (tool.injectDependencies) {
        tool.injectDependencies(this._dependencies);
      }

      this.register(tool);
    }
  }

  /**
   * 执行工具
   */
  async execute(name, input, context) {
    const tool = this.get(name);

    if (!tool) {
      throw new Error(`Tool not found: ${name}`);
    }

    const startTime = Date.now();
    const result = await tool.execute(input, context);
    const duration = Date.now() - startTime;

    // 记录执行日志
    logger.info('Tool executed', {
      tool: name,
      duration,
      success: result.success
    });

    return result;
  }
}

// 使用
const registry = new ToolRegistry();

// 手动注册
registry.register(new WebSearchTool());
registry.register(new FileSystemTool());

// 自动发现
await registry.discover(__dirname + '/tools');

// 执行
const result = await registry.execute('web_search', {
  query: '最新技术趋势'
}, { traceId });
```

## 十、单例模式

### 10.1 模式定义

**意图**: 保证一个类只有一个实例，并提供一个访问它的全局访问点。

**解决的问题**:
- 全局只需要一个实例
- 实例需要被全局共享
- 懒加载避免不必要的创建

### 10.2 应用场景：熔断器工厂

```javascript
// infra/circuitBreaker/CircuitBreakerFactory.js
/**
 * 熔断器工厂 - 单例模式
 */
class CircuitBreakerFactory {
  constructor() {
    // 私有构造函数，防止外部 new
    this._breakers = new Map();
    this._defaultOptions = {
      failureThreshold: 5,
      successThreshold: 3,
      timeout: 30000
    };
  }

  /**
   * 获取实例
   */
  static getInstance() {
    if (!CircuitBreakerFactory._instance) {
      CircuitBreakerFactory._instance = new CircuitBreakerFactory();
    }
    return CircuitBreakerFactory._instance;
  }

  /**
   * 获取熔断器
   */
  get(name, options = {}) {
    if (!this._breakers.has(name)) {
      this._breakers.set(name, new CircuitBreaker({
        name,
        ...this._defaultOptions,
        ...options
      }));
    }
    return this._breakers.get(name);
  }

  /**
   * 获取所有熔断器状态
   */
  getAllStatus() {
    return Array.from(this._breakers.entries()).map(([name, breaker]) => ({
      name,
      ...breaker.getState()
    }));
  }

  /**
   * 重置所有熔断器
   */
  resetAll() {
    for (const breaker of this._breakers.values()) {
      breaker.transitionTo(STATES.CLOSED);
    }
  }
}

// 导出单例
module.exports = CircuitBreakerFactory.getInstance();

// 使用
const breakerFactory = require('./CircuitBreakerFactory');

const breaker = breakerFactory.get('MiniMax-M2.7', {
  failureThreshold: 10
});

const result = await breaker.execute(
  () => llmClient.chat(messages),
  () => fallbackResponse
);
```
