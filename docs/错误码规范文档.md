## 一、错误码设计原则

### 1.1 错误码结构

```
错误码格式: XXXX
- 长度: 4 位数字
- 分类: 第 1 位表示大类 (1-5)
- 序列: 后 3 位表示具体错误
```

### 1.2 错误码分类

| 大类 | 范围 | 说明 | HTTP 状态码 |
|------|------|------|-------------|
| 1xxx | 认证授权类 | 用户认证、权限验证 | 401/403 |
| 2xxx | 参数校验类 | 请求参数校验失败 | 400 |
| 3xxx | 业务逻辑类 | 业务规则校验失败 | 400 |
| 4xxx | 外部依赖类 | 第三方服务调用失败 | 502/503 |
| 5xxx | 系统异常类 | 系统级别错误 | 500 |

## 三、错误响应格式

### 3.1 统一错误响应格式

```json
{
  "success": false,
  "code": "3201",
  "message": "Agent 不存在",
  "detail": "Agent ID: agent_xxx 不存在或已被删除",
  "traceId": "abc123def456",
  "timestamp": "2026-03-21T10:30:00.000Z",
  "path": "/api/agent/execute",
  "suggestion": "请检查 Agent ID 是否正确，或联系管理员"
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| success | boolean | 是 | 请求是否成功，错误时为 false |
| code | string | 是 | 错误码，4 位数字字符串 |
| message | string | 是 | 错误消息（用户友好） |
| detail | string | 否 | 错误详情（调试用） |
| traceId | string | 是 | 追踪 ID |
| timestamp | string | 是 | 错误发生时间 (ISO 8601) |
| path | string | 是 | 请求路径 |
| suggestion | string | 否 | 修复建议 |
| errors | array | 否 | 多字段校验错误列表 |
| metadata | object | 否 | 额外元数据 |

### 3.3 多字段校验错误

```json
{
  "success": false,
  "code": "2001",
  "message": "参数校验失败",
  "traceId": "abc123def456",
  "timestamp": "2026-03-21T10:30:00.000Z",
  "path": "/api/chat/send",
  "errors": [
    {
      "field": "message",
      "message": "消息内容不能为空",
      "code": "REQUIRED_FIELD"
    },
    {
      "field": "modelId",
      "message": "模型 ID 不在支持列表中",
      "code": "INVALID_VALUE"
    }
  ]
}
```

## 四、错误码使用规范

### 4.1 后端使用示例

```javascript
// common/errors/AppError.js
class AppError extends Error {
  constructor(code, message, options = {}) {
    super(message);
    this.name = 'AppError';
    this.code = code;
    this.httpStatus = options.httpStatus || 500;
    this.detail = options.detail || null;
    this.suggestion = options.suggestion || null;
    this.errors = options.errors || null;
    this.metadata = options.metadata || null;
  }

  toJSON() {
    return {
      success: false,
      code: this.code,
      message: this.message,
      detail: this.detail,
      traceId: tracer.getCurrentTraceId(),
      timestamp: new Date().toISOString(),
      path: req?.path,
      suggestion: this.suggestion,
      errors: this.errors,
      metadata: this.metadata
    };
  }
}
```

### 4.2 全局错误中间件

```javascript
// middleware/errorHandler.js
const { AppError } = require('../common/errors/AppError');

function errorHandler(err, req, res, next) {
  // AppError 直接处理
  if (err instanceof AppError) {
    return res.status(err.httpStatus).json(err.toJSON());
  }

  // 未知错误
  const internalError = new AppError('5001', '系统内部错误', {
    httpStatus: 500,
    detail: process.env.NODE_ENV === 'development' ? err.stack : null,
    suggestion: '请联系管理员或稍后重试'
  });

  return res.status(500).json(internalError.toJSON());
}
```

### 4.3 前端错误处理

```typescript
// lib/apiClient.ts
class ApiError extends Error {
  constructor(
    public code: string,
    message: string,
    public detail?: string,
    public suggestion?: string
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

async function handleResponse<T>(response: Response): Promise<T> {
  const data = await response.json();

  if (!data.success) {
    const error = new ApiError(
      data.code,
      data.message,
      data.detail,
      data.suggestion
    );
    error.code = data.code;
    throw error;
  }

  return data.data;
}

// 使用示例
try {
  const result = await apiClient.post('/api/chat/send', { message });
} catch (error) {
  if (error instanceof ApiError) {
    switch (error.code) {
      case '3205': // AGENT_TIMEOUT
        showToast('Agent 执行超时，请重试');
        break;
      case '3104': // CHAT_MESSAGE_TOO_LONG
        showToast('消息过长，请缩短后重试');
        break;
      default:
        showToast(error.message);
    }
  }
}
```
