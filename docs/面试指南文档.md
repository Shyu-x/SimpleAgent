## 二、核心项目亮点

### 2.1 ReAct Agent 执行引擎

**面试话术**:

> "我设计并实现了 ReAct Agent 执行引擎，核心是 Reason -> Act -> Observe -> Reflect 的循环。借鉴了 MiniMax Mini-Agent 的设计，实现了结构化日志、重试机制和取消机制。"

**STAR 描述**:

- **Situation**: 项目需要实现一个能执行复杂任务的 Agent 系统
- **Task**: 设计 Agent 执行引擎，支持工具调用、状态持久化、错误恢复
- **Action**:
  - 实现 ReAct 循环，Reason 阶段分析任务，Act 阶段执行工具
  - 集成 HITL 人机确认，危险操作需要用户确认
  - 实现 Token 自动摘要，防止上下文膨胀
- **Result**: Agent 可以自主完成多步骤任务，支持中断和恢复，Token 使用优化 80%

**代码示例**:

```javascript
// ReAct 循环核心
for (let i = 0; i < this.maxIterations; i++) {
  const thought = await this.think(currentContext);  // Reason
  if (thought.type === 'action') {
    const actionResult = await this.act(thought.tool, thought.input);  // Act
    currentContext.toolResults.push(actionResult);  // Observe
    if (this.llmEnabled) {
      const reflection = await this.reflect(thought);  // Reflect
      if (!reflection.shouldContinue) break;
    }
  }
}
```

### 2.2 多路检索架构

**面试话术**:

> "我设计了基于策略模式的多路检索架构，支持向量检索、关键词检索、混合检索并行执行，结果经过去重、重排序、阈值过滤后返回。"

**STAR 描述**:

- **Situation**: 知识库检索效果不佳，单路向量检索召回率低
- **Task**: 设计多通道并行检索系统，提升检索质量
- **Action**:
  - 定义 SearchChannel 抽象接口，每种检索方式独立实现
  - SearchCoordinator 作为门面，封装并行执行和结果合并
  - 后处理器链使用责任链模式，支持运行时动态配置
- **Result**: 检索质量提升 40%，新增检索通道只需实现接口，0 修改

**架构图**:

```
SearchCoordinator (门面)
    │
    ├── VectorSearchChannel (策略)
    ├── KeywordSearchChannel (策略)
    └── HybridSearchChannel (策略)
    │
    ▼
ProcessorChain (责任链)
    │
    ├── DeduplicationProcessor
    ├── RerankerProcessor
    └── ThresholdFilterProcessor
```

### 2.3 熔断降级机制

**面试话术**:

> "我实现了三态熔断器 (CLOSED -> OPEN -> HALF_OPEN)，配合模型路由器实现自动故障转移。当模型失败率达到阈值时自动熔断，冷却后进入半开探测，成功则恢复。"

**STAR 描述**:

- **Situation**: 生产环境中 LLM API 不稳定，偶发超时导致用户体验差
- **Task**: 设计熔断降级机制，防止级联失败
- **Action**:
  - 实现三态熔断器，CLOSED 正常、OPEN 熔断、HALF_OPEN 探测
  - 配合首包探测装饰器，确保模型切换时用户无感知
  - 模型路由器按优先级尝试候选模型
- **Result**: 模型故障自动切换，用户无感知，故障恢复时间从 5 分钟降到 10 秒

**代码示例**:

```javascript
class CircuitBreaker {
  async execute(fn, fallback) {
    if (this.state === STATES.OPEN) {
      if (Date.now() < this.nextAttempt) {
        return fallback ? fallback() : null;
      }
      this.state = STATES.HALF_OPEN;
    }

    try {
      const result = await fn();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      return fallback ? fallback() : null;
    }
  }
}
```

**面试话术**:

> "我设计了基于模板方法模式的文档入库流水线，每步作为独立节点执行，包含解析、清洗、分块、向量化、索引。节点独立日志，出问题能精确定位。"

- **Result**: 出问题能定位到具体节点，节点执行时间可追踪

## 三、架构设计问题

### 3.1 为什么选择这个架构？

**回答**:

> "架构选择基于以下考量：
> 1. **前后端分离**：前端 React 负责 UI，后端 Express 负责业务逻辑，职责清晰
> 2. **分层架构**：routes/application/domain/infra 四层，便于扩展和维护
> 3. **事件驱动**：使用 SSE 实现流式响应，用户体验好
> 4. **策略模式**：检索、工具等都使用策略模式，便于扩展"

### 3.2 如何保证系统稳定性？

**回答**:

> "通过多层保障：
> 1. **熔断器**：模型调用使用熔断器，故障自动隔离
> 2. **限流**：多层级限流（全局/用户/端点）
> 3. **重试**：带指数退避的重试机制
> 4. **监控**：全链路 Trace，每个环节耗时可查
> 5. **降级**：核心功能可降级，确保系统可用"

### 3.3 如何处理高并发？

**回答**:

> "高并发处理策略：
> 1. **流式响应**：SSE 避免长连接占用线程
> 2. **限流**：Redis + 信号量控制并发数
> 3. **缓存**：热点数据缓存，减少模型调用
> 4. **队列**：削峰填谷，请求排队处理"

## 四、技术深度问题

### 4.1 ReAct 循环如何避免死循环？

**回答**:

> "通过多层防护：
> 1. **最大迭代次数**：maxIterations 配置默认 10
> 2. **Token 限制**：超过阈值自动摘要
> 3. **反思机制**：LLM 判断是否继续
> 4. **去重检测**：检测相似历史决策"

### 4.2 如何保证 Token 使用最优？

**回答**:

> "Token 优化策略：
> 1. **自动摘要**：消息超过阈值时自动压缩历史
> 2. **上下文组装**：只包含相关历史消息
> 3. **模型选择**：简单任务用小模型，复杂任务用大模型
> 4. **缓存**：相同 Query 的响应缓存"

### 4.3 RAG 如何提升检索质量？

**回答**:

> "多维度优化：
> 1. **多路检索**：向量 + 关键词混合
> 2. **查询改写**：补全省略信息、同义词扩展
> 3. **查询拆分**：复杂问题拆成子问题
> 4. **重排序**：LLM 评估相关性重新排序
> 5. **智能分块**：语义分块而非固定大小"

## 五、场景题

### 5.1 如果模型响应很慢怎么办？

**回答**:

> "分层处理：
> 1. **超时控制**：设置合理超时，超时自动切换
> 2. **首包探测**：快速失败，避免等待
> 3. **流式输出**：边生成边展示，减少感知延迟
> 4. **降级方案**：模型不可用时返回缓存或默认回答
> 5. **监控告警**：响应超时及时通知"

### 5.2 如果需要支持 1000 并发？

**回答**:

> "扩容方案：
> 1. **水平扩展**：多个后端实例，无状态设计
> 2. **限流**：Redis 分布式限流
> 3. **队列**：请求入队列，异步处理
> 4. **缓存**：热点结果缓存
> 5. **CDN**：静态资源缓存"

### 5.3 如何防止 Prompt 注入？

**回答**:

> "多层防护：
> 1. **输入过滤**：检测注入模式并拦截
> 2. **Prompt 隔离**：用户输入不直接拼入系统 Prompt
> 3. **输出过滤**：对输出内容进行安全检测
> 4. **日志审计**：记录异常尝试
> 5. **沙箱**：危险操作在隔离环境执行"
